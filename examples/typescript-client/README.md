# TypeScript client example (generated Soroban bindings)

This example shows how a wallet/dApp frontend integrates with `asset-token`
using the TypeScript bindings generated by the Stellar CLI, instead of raw
`stellar contract invoke` calls.

## Prerequisites

- Stellar CLI >= 22 (`stellar --version`)
- Node.js >= 18 and npm
- A local network running with the contract deployed (see below)

## 1. Build the contract

From the repository root:

```sh
make build
```

This produces `target/wasm32v1-none/release/asset_token.wasm`.

## 2. Generate the bindings

The generated package is checked in nowhere: it is regenerated from the wasm
so it always matches the contract interface.

```sh
npm run generate
```

This runs:

```sh
stellar contract bindings typescript \
  --wasm ../../target/wasm32v1-none/release/asset_token.wasm \
  --output-dir bindings \
  --overwrite
```

## 3. Deploy against a local network

Start a local network (for example `stellar network container start local`),
register it with the CLI, and deploy the contracts with `scripts/deploy.sh`:

```sh
NETWORK=local IDENTITY=alice ./scripts/deploy.sh
```

Copy the printed asset-token contract ID and the admin address into a `.env`
file in this directory (see `.env.example`). The admin must already be
allowlisted on the compliance contract; `scripts/deploy.sh` does this for you.

## 4. Run the example

```sh
npm install
npm run example
```

The script generates a fresh recipient address, calls `balance` for the admin,
checks the recipient's balance before the transfer, calls `transfer`, and then
reads both balances again. All calls go through the generated `Client`, which
signs and submits the transactions via the configured RPC endpoint.

## Generated client API

The generated `Client` exposes one async method per contract function. Each
method accepts an object with the contract argument names, for example:

```ts
const before = await client.balance({ address: alice });
await client.transfer({ from: alice, to: bob, amount: 100n });
const after = await client.balance({ address: bob });
```

See [QUICKSTART.md](../../QUICKSTART.md) for the equivalent raw CLI calls and
for testnet deployment instructions. The same generation command works for
`compliance`, `dividend`, and `registry` by pointing `--wasm` at another wasm
file in `target/wasm32v1-none/release/`.
